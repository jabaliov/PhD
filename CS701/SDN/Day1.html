0. بوابة الـ Prerequisites

قبل أن نبني mental model، نتحقق من أساسيات سريعة. لا تحتاج تفاصيل عميقة؛ المطلوب فقط أن تفهم الصورة.

1) ما الفرق العام بين جهاز المستخدم وWeb Server؟
2) عندما تكتب اسم موقع، هل الاسم نفسه هو العنوان الذي تستخدمه الشبكة للوصول إلى الجهاز؟
3) ما الذي يقدمه DNS بصورة مبسطة؟
4) لماذا نحتاج TCP في المثال الموجود في السلايدات؟
الإجابات النموذجية
1) كلاهما Host، لكن أحدهما Client في المثال والآخر Web Server يقدم الخدمة.
2) لا. السلايدات تشرح أن Domain Name يحتاج إلى ترجمة إلى IP Address بواسطة DNS.
3) DNS Query/Reply تُستخدم للحصول على IP Address المرتبط باسم النطاق.
4) السلايدات تستخدم TCP Connection لنقل بيانات التطبيق؛ وتوضح أن HTTP request تُرسل عبر TCP وتُغلف في TCP Segment.

1. ابدأ من المشكلة: لدينا Laptop يريد الوصول إلى Server

تخيل أنك فتحت المتصفح وطلبت صفحة من Web Server. السؤال الذي يهمنا اليوم ليس "ما هو SDN؟"، بل:

ما الذي يتحرك فعليًا من Laptop إلى Server؟ وهل تتحرك الرسالة نفسها، أم شيء آخر؟

السلايدات تبدأ بمثال Bob الذي يعرف اسم النطاق ويستخدم Web Browser للوصول إلى Web Server، ثم تمر عبر DNS وTCP وIP وMAC/Ethernet حتى تصل البيانات إلى الطرف الآخر.

2. Network

المشكلة

جهازان لا يستطيعان تبادل البيانات إذا لم توجد وسيلة تربطهما.

السؤال الطبيعي

ما اسم مجموعة الأجهزة والروابط التي تسمح بتبادل البيانات؟

المصطلح

Network — شبكة: مجموعة من الأجهزة المتصلة بروابط تسمح بتبادل البيانات.

Laptop ───── Link ───── Server \ / Network

اختبار الفهم

هل الـNetwork هو "سلك" فقط؟ لا. السلك قد يكون Link واحدًا؛ الشبكة هي المنظومة الأوسع.

3. Host وNode

السؤال الطبيعي

إذا كان لدينا أجهزة داخل الشبكة، كيف نصف الجهاز الذي يشارك في الاتصال؟

Host
جهاز نهائي (End System) يتعامل مع البيانات كتطبيقات وخدمات، مثل Laptop أو Server.
Node
مصطلح أوسع لنقطة/جهاز في الشبكة. لا تحصره تلقائيًا في أجهزة المستخدم فقط.
فخ مهم: كل Host يمكن اعتباره Node في الاستخدام العام، لكن ليس كل Node بالضرورة Host نهائيًا. لا تجعل المصطلحين مترادفين 100% في كل سياق.

4. Link

المشكلة

لدينا Laptop وRouter، لكن كيف تنتقل الإشارة من أحدهما إلى الآخر؟

المصطلح

Link هو وصلة الاتصال بين عقدتين متصلتين مباشرة، وقد تكون عبر Ethernet أو Wi‑Fi أو وسيلة أخرى.

[Laptop] ═════ Link ═════ [Network Device]

السلايدات تعرض access technology مثل Fiber, Cable, Wi‑Fi, Cellular كوسائل وصول.

5. NIC — نقطة خروج ودخول البيانات من الجهاز

السؤال الطبيعي

الجهاز لديه بيانات، لكن عبر أي واجهة يرسلها إلى الشبكة؟

NIC (Network Interface Card/Controller) هي واجهة الشبكة التي تمكّن الجهاز من الاتصال بالشبكة، مثل واجهة Ethernet أو Wi‑Fi.

Application ↓ Operating System ↓ NIC ↓ Network

فكرة لا تنساها: الـNIC هي "الباب" الذي يربط الجهاز بالشبكة.

6. الآن السؤال الأهم: ما الذي يتحرك؟

لنقل رسالة مثل:

"أريد حجز تذكرة طيران"

التطبيق لا يرسل هذه العبارة مباشرة عبر السلك. البيانات تمر بعمليات encapsulation (تغليف) بحيث تضيف الطبقات معلومات تساعد في النقل والتوصيل.

Application Data ↓ +-------------------------+ | TCP Header | Data | ← TCP Segment +-------------------------+ ↓ +--------------------------------+ | IP Header | TCP Segment | ← IP Datagram / Packet +--------------------------------+ ↓ +------------------------------------------------+ | Ethernet Header | IP Packet | Ethernet Trailer| ← Frame +------------------------------------------------+
تنبيه: هذا الرسم mental model تعليمي مبسط. أسماء الوحدات الدقيقة قد تختلف حسب الطبقة والسياق، لكن الهدف هنا تثبيت علاقة "بيانات داخل Segment داخل IP packet/datagram داخل Ethernet frame".

7. Packet

المشكلة

كيف نمثل وحدة بيانات يمكن للـIP layer التعامل معها عبر الشبكة؟

Packet هو مصطلح عام لوحدة بيانات تُرسل عبر الشبكة. وفي السلايدات، عند IP Layer يتم تغليف TCP Segment داخل IP Datagram.

إذن لا تحفظ: "Packet = شيء مستقل دائمًا". الأفضل: Packet وصف عام لوحدة بيانات شبكية، والسلايدات تستخدم IP Datagram كوحدة IP.

8. Header وPayload

السؤال الطبيعي

إذا كانت البيانات داخل Packet/Frame، كيف نعرف ماذا نفعل بها؟

Header
معلومات تحكم/وصف تساعد البروتوكول على معالجة البيانات: عناوين، أرقام منافذ، معلومات أخرى بحسب الطبقة.
Payload
الجزء الذي تحمله الوحدة من بيانات الطبقة الأعلى.
┌──────────── Header ────────────┬──── Payload ────┐ │ معلومات تساعد على المعالجة │ البيانات المحمّلة │ └────────────────────────────────┴──────────────────┘

9. IP Address — "إلى أي Host/شبكة؟"

المشكلة

إذا أردت الوصول إلى Server بعيد، تحتاج عنوانًا يمكن استخدامه في طبقة IP لتحديد الوجهة.

IP Address هو عنوان منطقي (Logical Address) يستخدمه IP لتحديد المصدر والوجهة على مستوى الشبكة.

في مثال السلايدات: اسم النطاق يحتاج أولًا إلى ترجمة إلى IP Address بواسطة DNS، ثم تُرسل البيانات في IP Datagram، وتقوم Routers بتمريره hop by hop اعتمادًا على Routing Tables.

www.example.com ↓ DNS 203.0.113.10 ↓ IP Destination

لا تخلط

DNS لا ينقل صفحة الويب. هو جزء من خطوة معرفة IP المرتبط بالاسم في المثال.

10. MAC Address — "إلى أي Interface على الوصلة المحلية؟"

المشكلة

لدينا IP للـnext-hop، لكن Ethernet يحتاج عنوان MAC للواجهة المقصودة على الوصلة المحلية.

MAC Address هو عنوان مرتبط بواجهة الشبكة على مستوى Ethernet/Link Layer.

السلايد الخاص بـARP يوضح أن Ethernet Frame يجب أن يصل إلى interface الخاصة بالـnext-hop router، وأن ARP request/reply تُستخدم لحل MAC Address.

IP Address of next hop ↓ ARP ↓ MAC Address of next-hop interface ↓ Ethernet Frame

IP AddressMAC Address
الفكرةعنوان منطقي على مستوى IPعنوان واجهة على مستوى Ethernet
السؤال المبسطإلى أي وجهة شبكية؟إلى أي Interface على الوصلة المحلية؟

العلاقةليس أحدهما بديلًا عن الآخر؛ كل واحد يخدم طبقة/وظيفة مختلفة.

12. Ethernet وFrame

السؤال الطبيعي

بعد أن أصبح لدينا IP Datagram، كيف نضعه على وصلة Ethernet المحلية؟

Ethernet يحدد آلية وformat لإطار البيانات على وصلة Ethernet.

Frame هو وحدة البيانات التي تحمل IP Datagram داخل Ethernet في المثال.

Ethernet Frame ┌───────────────┬───────────────────────┬──────────────┐ │ Ethernet Hdr │ IP Packet │ Trailer │ └───────────────┴───────────────────────┴──────────────┘

السلايدات تقول صراحة: The IP datagram is encapsulated in an Ethernet frame.

13. Port — لماذا IP وحده لا يكفي؟

المشكلة

تخيل أن جهازًا واحدًا يشغّل Browser وEmail وSSH في الوقت نفسه. إذا وصلت البيانات إلى الجهاز، لأي تطبيق يجب تسليمها؟

Port رقم منطقي يستخدم مع بروتوكولات النقل (مثل TCP/UDP) لتمييز endpoint/application داخل الـHost.

السلايدات تذكر أن port number يُحمل في عملية TCP، وأن HTTP request تُرسل عبر TCP connection.

IP Address → يحدد الـHost Port → يساعد في تحديد التطبيق/الخدمة داخل الـHost IP + Port ↓ TCP/UDP Endpoint

14. المثال الكامل — Laptop → Web Server

هذه أهم فقرة في Day 1. لا تحفظ المصطلحات منفصلة؛ اتبع الرحلة.

① المستخدم يكتب Domain Name ↓ ② DNS Query → DNS Server ↓ ③ DNS Reply ← IP Address ↓ ④ Browser يستخدم HTTP ↓ ⑤ TCP Connection ↓ ⑥ HTTP Request داخل TCP Segment ↓ ⑦ TCP Segment داخل IP Datagram ↓ ⑧ IP Datagram داخل Ethernet Frame ↓ ⑨ ARP يساعد في معرفة MAC للـnext-hop على الوصلة المحلية ↓ ⑩ Routers تمرر IP Datagram hop-by-hop ↓ ⑪ Server يستقبل Frame ↓ ⑫ البيانات تصعد إلى الطبقات الأعلى ↓ ⑬ Application تستقبل HTTP Request وترسل HTTP Response

هذا التسلسل مستند مباشرة إلى سلسلة الأمثلة في Review slides: Application → DNS → TCP → IP → MAC/Ethernet → ARP → الطرف الآخر.

15. Worked Example — لماذا يتغير Frame بينما تستمر الوجهة IP؟

افترض أن Laptop يريد الوصول إلى Server بعيد عبر Router أول.

Laptop Router 1 Server │ │ │ │ Frame A │ │ │ Dst MAC = Router1 │ │ ├──────────────────────────────>│ │ │ IP Dst = Server │ │ │ │ Frame A انتهى هنا │ │ │ │ │ │ Frame B │ │ │ Dst MAC = Next Hop │ │ ├─────────────────────────>│ │ │ IP Dst = Server │

الفكرة: الـEthernet Frame مرتبط بالوصلة المحلية الحالية، بينما الـIP Datagram يمثل الوجهة على مستوى IP. لذلك لا تتعامل مع MAC وIP كأنهما عنوانان يؤديان الوظيفة نفسها.

16. لماذا هذا مهم لـSDN؟

السلايدات الخاصة بـSDN ستبني لاحقًا على فكرة أن الشبكات لها Control Plane وData Plane، وأن Data Plane مسؤولة عن تنفيذ السلوك على الـPackets.

لكننا لن نشرح Control Plane وData Plane اليوم. اليوم نحتاج فقط أن تكون لديك صورة واضحة عن الشيء الذي سيقوم الـData Plane بمعالجته: Packet/Frame، وأن تعرف الفرق بين IP وMAC وأن تفهم encapsulation.

سنعود لهذا لاحقًا: Switch, Router, Routing, Forwarding, Control Plane, Data Plane, OpenFlow, Flow Table, Controller.

17. اختبار الفهم — Why / How / What if / Compare / Trace

Why? لماذا نحتاج DNS قبل أن نبدأ الاتصال بالـWeb Server عندما نملك Domain Name فقط؟
How? كيف تتحول HTTP Request إلى شيء يمكن إرساله عبر الشبكة؟
What if? ماذا يحدث مفاهيميًا إذا كان IP معروفًا لكن MAC الخاص بالـnext-hop غير معروف على Ethernet؟
Compare قارن IP Address وMAC Address في جملة واحدة.
Trace تتبع HTTP Request من Browser حتى Ethernet Frame.
إجابات مختصرة
DNS: للحصول على IP المرتبط باسم النطاق في المثال.
HTTP Data → TCP Segment → IP Datagram/Packet → Ethernet Frame.
تُستخدم ARP Request/Reply لحل MAC Address للـnext-hop interface وفق السلايدات.
IP يحدد الوجهة على مستوى IP؛ MAC يحدد واجهة على وصلة Ethernet المحلية.
Browser/HTTP → TCP → IP → Ethernet، مع ARP عند الحاجة إلى MAC للـnext hop.

18. Common Confusions

  • Packet ≠ Frame: الـFrame هو وحدة Link/Ethernet التي تحمل IP Packet في مثالنا.
  • IP ≠ MAC: لكل منهما وظيفة ومستوى مختلف.
  • DNS ≠ Internet: DNS خدمة لترجمة الأسماء إلى IP في هذا السيناريو.
  • Port ≠ IP: IP يساعد في تحديد Host؛ Port يميز endpoint/application داخل Host.
  • Host ≠ Link: Host جهاز؛ Link وصلة.
  • NIC ≠ Network: NIC واجهة الجهاز التي توصله بالشبكة.
  • لا تقفز إلى Routing الآن: السلايدات تذكر Routing Tables، لكن فهم آلية Routing/Forwarding التفصيلية مؤجل إلى Day 2.

21. Exam Questions

  1. What is the difference between a Packet and a Frame?
    الإجابة: Packet مصطلح عام لوحدة بيانات شبكية، وفي مثالنا IP Datagram؛ Frame وحدة Link/Ethernet تحمل الـIP Packet.
  2. Why do we need both IP and MAC addresses?
    الإجابة: لأنهما يخدمان وظيفتين مختلفتين: IP على مستوى الشبكة، وMAC لتوصيل Frame عبر وصلة Ethernet المحلية.
  3. What is encapsulation?
    الإجابة: إضافة معلومات الطبقة الحالية حول بيانات الطبقة الأعلى، بحيث تصبح وحدة بيانات قابلة للمعالجة والنقل في تلك الطبقة.
  4. What does a Port identify?
    الإجابة: endpoint/application داخل Host في سياق TCP/UDP.
  5. Trace an HTTP request.
    الإجابة المختصرة: HTTP → TCP Segment → IP Datagram → Ethernet Frame.
